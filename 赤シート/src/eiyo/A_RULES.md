# 一問一答（穴埋め）形式 a_<m>.py の作り方（解剖生理学Ⅰ）

## 背景と学生の条件
看護学部1年の再テスト（75〜80点目標、解剖1は10/13）用の赤シート教材。市販の一問一答集のように
「左：空欄つきの文」「右：赤字の答え＋用語解説＋図」の形式にする。見本は a_lymph1.py（完成版）。
- **太字・色文字（赤・青）・下線、その他テストに出そうなものだけを、漏れなく**問題にする。**各回（1ファイル）上限88問**
- 問題・答えの間違いは絶対ダメ。余計な問題（雑学・「参考」・テストに出なさそうなもの）は入れない
- A4・赤シート：{…} や答え欄は赤字で隠れる。図の中の文字も赤字に塗り替えて隠す（figtool が自動でやる）

## 材料
- <m>.py：検証済みの問題データ（{…}が答え）。**これが事実の土台**。この中の答えは全部、A のどこかで必ず隠れた答えにする。
- colorU_<m>.txt：スライド本文（[赤:…][青:…]、**太字**、<u>下線</u>、[紫:…]教科書ページ）。pdf/<m>.pdf が原本。
- 解説・追加問題に使ってよいのは、スライド（本文＋先生のノート＋図）に書いてあることだけ。教科書と違う所は「※試験はスライドどおり」の注意（答えを明かさない）。

## 書式（a_lymph1.py を必ず読んで真似る）
```
SECTIONS = [ (セクション名, [ (star, "文［1］…［2］…", ["答え1", "答え2|よみ", …], "解説[[fig|…]]"[, "id"]), … ]), … ]
```
- セクション名・順番は <m>.py と同じにする（見出しは赤字で隠れる）。
- 1問 = 1つの自然な平叙文。答えの位置を［1］［2］…の空欄にし、答えリストの数と一致させる（同じ空欄の再使用は可）。
- 元の1問は原則A の1問にするが、長すぎる問題は2問に分けてよい。元の答え {…} の中身は必ずどこかで隠れた答えになること。
- 元の長い答え（句・文）は、無理に長い空欄にしない。要の語を空欄にし、残りの語句は解説の赤字 {…} に入れればよい（check_ab は解説の赤字も「隠れた答え」として数える）。
- **追加問題**：色・太字ではないが試験に出やすい事実（定義、数値、分類、名称、働き、正常値、病名と原因・症状、順番、比較）で、まだどの問題にもなっていないものを追加してよい（同じセクションの適切な位置に）。上限88問を超えない。雑学・参考・症例紹介などは入れない。
- star：元の★を引き継ぐ。追加問題は、赤字かつ太字の項目か先生が「重要」「★」と明記したものだけ1、他は0（✴・✓は箇条書き記号）。
- 見える文字（空欄以外の文、解説の {} 外、図のキャプション）に、その問題の答えを書かない。他の問題の答えもできるだけ書かない（二択の選択肢として出すのは可）。問題どうしの参照は「No.@id」（5番目の要素に英字ID）。
- **ふりがな**：難しい医学用語の漢字には、答えなら "語|よみ"、文中なら 《語|よみ》、解説中の赤字なら {語|よみ}。読みは絶対に正確に（自信がないものは付けない）。
  - 答えの中で語のあとに仮名が続くとき（例「陥没した部分」）は、答えの中でも 《陥没|かんぼつ》した部分 と書けばルビが付く（空白を入れるなどの工夫は不要）。
- **解説**：ほぼ全問に1〜3文。スライドのノートの補足・理由・関連事項（例：「〜なので〜」「図の〜を確認」）。解説中に答えとなる語が出るときは {…} で赤字に。

## 図・写真
- スライドの図を使う：`python3 -c "import figtool; print(figtool.grid('<m>', <スライド番号>))"` で目盛り付きのスライド画像（figs/grid_…png）を作り、Read で見て、**図の部分だけ**を囲む範囲（0〜1の相対座標、0.1刻みの目盛り）を決める。タイトル帯や余白は入れない（文字が大きく見えるように、できるだけきつく）。
- 解説の**最後**に `[[fig|fig:<m>:<スライド番号>:x0,y0,x1,y1|スライド<番号>の図]]` と書く（解説欄の幅いっぱいに表示される）。
- 図のあるスライド（構造図・イラスト・写真・グラフ・表の図）は、関係する問題に1回ずつ入れる。文字だけのスライドは入れない。同じ図を何度も入れない。
- **画像に埋め込まれた文字**（PDFの文字でないラベル）は自動では赤くならない。答えが見えてしまうときは `:R=x0,y0,x1,y1`（スライド内の相対座標、複数は / 区切り）を付けると、その範囲の濃い画素が赤になり赤シートで隠れる：`[[fig|fig:<m>:<n>:x0,y0,x1,y1:R=0.5,0.4,0.7,0.46|スライドnの図]]`
- 作ったあと `python3 -c "import figtool; print(figtool.render('fig:<m>:<n>:x0,y0,x1,y1'))"` で出力JPEGを Read して、図が切れていないか・文字（赤字に変わる）が読める大きさかを確認する。
- **ネットの写真・イラスト**（必要なときだけ、1ファイル数枚まで）：スライドに図がない重要事項で、正確な画像があると理解が深まる場合（病気の外観写真、構造の写真など）。
  - `python3 webimg.py search "英語のキーワード"` → 候補（タイトル｜ライセンス｜サイズ｜説明）、`python3 webimg.py get "File:…"` で取得。
  - 条件：ウィキメディア・コモンズの自由ライセンス（PD/CC0/CC BY/CC BY-SA）のみ／内容が正確（説明文で確認）／**英語などの文字ラベルが入っていないもの**（ラベルは赤シートで隠れないため）。
  - 書き方：`[[fig|web:File:ファイル名.jpg|写真：…（何の写真かを正確に。答えは {…} で赤字）]]`（出典は自動で付く）。
  - 429エラー（アクセス過多）が出たら少し待って再試行、だめなら使わない。

## 仕上げ（必ず）
1. `python3 check_ab.py <m>` の A の指摘をゼロに（[要確認] は内容を見て判断、二択の選択肢などは可）。
2. `FORMAT=a COURSE=course1 ONLY=<m> python3 render_ab.py preview/chkA_<m>.pdf` がエラーなく終わること。できたPDFの数ページを PNG にして見た目（図の大きさ・文字の読みやすさ）を確認。
3. 全問を元の <m>.py とスライドに照らして読み直し、事実が変わっていない・日本語が自然・ふりがなが正しいことを確認。
4. 報告（短く）：問題数（元の数→最終）、追加した問題の概要、図の数（スライド／ネット）、迷った点。
